# 🌙 dream: the declapract.upgrade 3.3 stone prescribes a commit header that git.commit.set refuses on feat branches

- kind: reseed
- owner: ehmpathy/rhachet-roles-ehmpathy (mechanic, declapract.upgrade templates)
- caught 2026-11-21

## .the cue that fired

on ehmpathy/domain-objects pr #144, the stone's own step 2 command failed: `✋ ConstraintError: commit prefix mismatch`, `level.bound = feat (inferred)`, `level.found = fix`.

## .the gap, precisely

- `src/domain.roles/mechanic/skills/declapract.upgrade/templates/3.3.repair.cicd.defects.stone:16` hardcodes `printf 'fix(practs): bump to latest best…'`
- `git.commit.set` infers the branch level from the branch name; `beav/feat-declapract-upgrade` binds `feat`, so a `fix` header is refused
- the header is also cut short: `bump to latest best` (no `practices`)
- a documented command that fails costs a round trip and invites a driver to improvise a header

## .the shape of the fix

- the template names the level as a choice: `printf '<fix|feat>(practs): bump to latest best practices…'`, with one line: "use the level your branch is bound to (`git.commit.set` names it on refusal)"
- or the upgrade init skill binds the branch level to `fix` on route creation, so the template and the bind agree
- clamp: the template's snapshot test (if any) asserts the header reads `best practices`

## .why it is not done in this round

the template lives in another repo; this route only upgrades domain-objects. the local cost was one refused try, fixed by the refusal's own hint.
