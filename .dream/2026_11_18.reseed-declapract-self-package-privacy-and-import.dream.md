# 🌙 dream: declapract-typescript-ehmpathy breaks the domain-objects repo itself

- kind: reseed
- owner: ehmpathy/declapract-typescript-ehmpathy
- caught 2026-11-18

## .the cue that fired

`declapract.upgrade` on ehmpathy/domain-objects (0.47.70 → 0.50.0) failed `test:types`. fixed locally; the fix is overwritten on each future upgrade.

## .the gap, precisely

two practices assume the adopter CONSUMES `domain-objects`. the domain-objects repo IS that package:

- `src/practices/provision-github/best-practice/provision/github.repo/resources.ts:14` writes `import { type DomainEntity, RefByUnique } from 'domain-objects';`
- `src/practices/domain/best-practice/package.json:3` wants `"domain-objects": "@declapract{check.minVersion('0.34.0')}"`. in domain-objects, declapract declines it (`⚠️ warn: omit self-dependency`)
- result: the provision import has no module → TS2307

`link:.` (the `node/self-deps-not-link` convention) does not rescue it here: a self-link resolves through `main` (`dist/index.js`), so type checks would need a built `dist`, and the CI `test-types` job does not build.

## .the shape of the fix

pick one, upstream:

- provision template: when `package.json#name === 'domain-objects'`, emit `from '../../src'`
- or: have `declastruct-github` re-export `DomainEntity` + `RefByUnique` (the template uses only these), and import them from there. this drops the template's dep on `domain-objects` for every adopter
- `domain` practice: skip the `domain-objects` dep when `package.json#name === 'domain-objects'`, so the warn stops

## .not part of this dream

the `"private": true` backfill is BY DESIGN (`rule.forbid.fail-open-publicity`): public is an owner opt-in. a published package declares `"private": false` by hand. no upstream change owed.

## .why it is not done in this round

the fix belongs to another repo; this route only upgrades domain-objects.
