## D-1: practice bug

citations (`rhx git.repo.get lines --in ehmpathy/declapract-typescript-ehmpathy`, ref origin/main):

- `src/practices/provision-github/best-practice/provision/github.repo/resources.ts:14` → `import { type DomainEntity, RefByUnique } from 'domain-objects';`
- `src/practices/domain/best-practice/package.json:3` → `"domain-objects": "@declapract{check.minVersion('0.34.0')}"`. in this repo declapract core declines it: `⚠️ warn: omit self-dependency` (exec log)

confirmed on github via `gh search code --repo ehmpathy/declapract-typescript-ehmpathy` (commit `9b0da94`):

- https://github.com/ehmpathy/declapract-typescript-ehmpathy/blob/9b0da949d344da643227bcda93230c5572472f78/src/practices/provision-github/best-practice/provision/github.repo/resources.ts
- https://github.com/ehmpathy/declapract-typescript-ehmpathy/blob/9b0da949d344da643227bcda93230c5572472f78/src/practices/domain/best-practice/package.json

why it is a bug, not a quirk: the template ships a hard import with no guard for the one adopter that IS the package, and each upgrade rewrites the file (`FIX_AUTOMATIC`), so the local fix does not survive. only one adopter is hit, so severity is low.

why the sanctioned self-reference does not fit: `node/bad-practices/self-deps-not-link` sanctions `"<self>": "link:."`. a self-link resolves through `main` → `dist/index.js`, so `tsc --noEmit` would need a built `dist`; the CI `test-types` job does not build. so `'../../src'` is the right local fix, and the cure belongs upstream.

local fix: `import { type DomainEntity, RefByUnique } from '../../src';` (main's exact line).

upstream: dream `dreams/v2026_11_18.reseed-declapract-self-package-privacy-and-import.md` (guard the template on `name === 'domain-objects'`, or import these two symbols via `declastruct-github`; skip the `domain` practice's self-dep).

## D-2: repo quirk; the practice is correct

citations (same repo, origin/main):

- `.agent/repo=.this/role=any/briefs/rule.forbid.fail-open-publicity.md` → visibility fails closed; public is an explicit, per-repo opt-in; "a published package declares `"private": false` by its owner's hand; its next publish fails loud until it does, which is the safe direction"
- `src/practices/provision-github/best-practice/.declapract.readme.md:16-19` → same contract
- `src/practices/provision-github/bad-practices/implicit-package-privacy/package.json.declapract.ts:31` → an explicit boolean is never touched

so the backfill did what it promises: it made an implicit visibility explicit, toward closed. the quirk is this repo's: it is public and on npm, yet never declared so, because main's provision read absence as public.

local fix: `"private": false`. upstream says the owner, not a practice, writes that line. the driver wrote it on the evidence of the owner's prior choice (`gh repo view` → `PUBLIC`; `npm view domain-objects version` → `0.34.0`) → fulcrum `F1` (92%, clean rework), owner confirms at review. once declared, it sticks across upgrades.

not an adoption candidate: other public packages owe the same line, but by their owners' hands, which the upstream readme already tells them.
