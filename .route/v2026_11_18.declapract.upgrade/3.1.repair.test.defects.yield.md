## defect inventory

### D-1: TS2307, cannot find module `'domain-objects'`

- **what**: `test:types` failed: `provision/github.repo/resources.ts(14,48): error TS2307: Cannot find module 'domain-objects'`
- **how**: `git diff origin/main -- provision/github.repo/resources.ts` → the template swapped `import { type DomainEntity, RefByUnique } from '../../src'` for `from 'domain-objects'`
- **why**: two practices assume a consumer repo that depends on `domain-objects`. `provision-github` writes the import; `domain` tries to add the dep itself (`domain-objects@check.minVersion('0.34.0')`), which declapract declined with `⚠️ warn: omit self-dependency`, logged in the package.json fix block beside `practice:domain.best-practice`. this repo IS `domain-objects`, so the dep never lands and the import has no module to load
- **fix**: restore main's exact line, `import { type DomainEntity, RefByUnique } from '../../src';` (stone 1). the origin/main diff now shows that line as unchanged context. proof: `rhx git.repo.test --what types --mode apply` → `🎉 passed`

### D-2: `"private": true` on a published package

- **what**: not a test failure, but a publish break: `implicit-package-privacy` added `"private": true`
- **how**: `git diff origin/main -- package.json provision/github.repo/resources.ts` → two coupled changes:
  - package.json: `+  "private": true,` (main had no `private` key)
  - provision: `visibility: pkg.private === true ? 'private' : 'public'` (absent → public, fail open) became `pkg.private === false ? 'public' : 'private'` (absent → private, fail closed)
- **why**: the template flipped the default to fail closed AND stamped `true`. either change alone makes the repo private on the next provision apply; with `true`, `npm publish` also refuses. domain-objects is a public npm package (`.publish-npm.yml`)
- **fix**: `"private": false` (stone 1). under the new fail-closed rule, only an explicit `false` keeps the repo public. upstream reserves that line for the repo owner (`rule.forbid.fail-open-publicity`), so it is a best-guess on the owner's prior choice (repo `PUBLIC`, `0.34.0` on npm) → fulcrum `F1`, owner confirms at review

### D-3: boot spec over budget (stop hook halt)

- **what**: `rhachet roles cost --all --when hook.onStop` → `✋ ConstraintError: .agent/repo=.this/role=any/boot.yml (7,354 / 5,000 tokens)`
- **how**: `.agent/repo=.this/role=any/boot.yml` is new in this upgrade (`FIX_AUTOMATIC`, `rhachet.best-practice`). it caps the say payload at 5,000 tokens with no `say`/`ref` entries, so every repo brief boots in full

- **fix**: `ref: [briefs/define.*.md]` in that boot.yml; the briefs stay addressable by path. `rhx cost --what .agent/repo=.this/role=any/boot.yml` → 336 / 5,000. class: repo quirk (this repo's own brief corpus); the boot.yml header says an upgrade keeps own entries, so it does not recur
