## defect found + fixed in execution

**strict schema rejected the `_dobj` key.** the `_dobj` discriminator is a serialization artifact, not a domain field. with strict schemas, `.build(prop)` re-validated `prop` (which still carried `_dobj`) and zod rejected it as an unrecognized key. the extant schemaless `PlantPot`/`PlantBed` test never hit this (no schema = no validation). fix: strip `_dobj` into `propToBuild` before we construct any option. covered by case3.t1 and case4.t0.

### r2 (mech-failhides) — reasoned disagreement, escalated

r2 flags the `typeof nestedProp !== 'object' || nestedProp === null` skip as a failhide blocker and proposes a throw. i disagree, for these reasons:

- **prior + out-of-scope.** this branch predates issue #124 (an additive multi-option feature); i only reshaped the guard from `return;` to `return hydratedProps;` for the immutable reduce.
- **the proposed throw is incorrect.** `typeof null === 'object'`, so the suggested "throw unless object or null" would in fact throw on legitimate `null` and break the extant test `DomainObject.test.ts:252` ("should not hydrate nullable nested domain objects when null").

- **sibling reviewer downgrades it.** r7 flags the identical line as only a nitpick and accepts in-contract documentation as resolution — which is now provided in the JSDoc `.note`.

recommendation: keep the lenient skip (documented), do not change prior null/optional semantics inside an additive feature branch. needs wisher ratification.

## approach A vs B — resolved by wisher (2026-07-06)

r8 (behavior-intent-coverage) flagged the code-vs-vision gap: vision said approach B (fail if **any** option is non-strict); code does approach A (fail if an option that **validates the input** is non-strict). escalated to the wisher.

**wisher decided: keep A, align the vision text.** rationale: strictness is checked by a lib-agnostic behavior-probe (add an unknown key, see if the schema still accepts), which is only meaningful against an object the schema accepts. approach B would require per-lib schema introspection (zod catchall, joi unknown flag, yup noUnknown) — the fragile route rejected earlier — for zero runtime-safety gain, since a superset can only be mis-mapped into an option whose schema accepts it, and A strict-checks every option that accepts the input.

changes made:
- `1.vision.yield.md` updated throughout (one-breath summary, order-of-ops table step 3, strict-mandatory paragraph, edgecases, open-question q4, awkward notes) to describe A precisely, with a 2026-07-06 note on why.
- added test case5.t2 — a non-strict option that does **not** accept the input does **not** failfast; hydration settles into the strict option that fits. documents the A boundary.
