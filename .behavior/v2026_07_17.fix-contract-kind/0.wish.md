# feat: publish a `DomainObjectContract` type + stamp `kind` onto the `.contract` pragma

## handoff from: sdk-aws-lambda · feat-sdk-codegen

### context

the `.contract` getter (shipped in domain-objects@0.32.0) stamps an
`x-domain-object` pragma onto a dobj's zod schema so a cross-service consumer can
name, de-dupe, and reconstruct the upstream dobj from the wire. today the pragma is:

```js
// getContract.js
const pragma = {
  name: dobj.name,
  ...(dobj.primary ? { primary: dobj.primary } : {}),
  ...(dobj.unique  ? { unique:  dobj.unique  } : {}),
  ...(dobj.alias   ? { alias:   dobj.alias   } : {}),
  ...(dobj.nested  ? { nested:  toNestedNames(dobj.nested) } : {}),
};
```

`sdk-aws-lambda` codegen consumes this pragma. it hit two rough edges that
domain-objects is the right home to smooth:

---

### ask 1 — publish a `DomainObjectContract` type

there is no exported type for the *parsed* pragma shape. so `sdk-aws-lambda` had to
hand-roll its own local `DomainObjectContract` domain-object to represent it:

```ts
// sdk-aws-lambda: src/domain.objects/DomainObjectContract.ts (local, invented)
interface DomainObjectContract {
  name: string;
  kind: 'entity' | 'literal';
  primary: string[];
  unique: string[];
  alias: null | string | { singular?: string; plural?: string };
  nested: Record<string, string | string[]>;
  shape: JSONSchema;
}
```

**the ask:** publish this as a first-class `DomainObjectContract` type (+ ideally a
transformer that parses an `x-domain-object` pragma node → `DomainObjectContract`),
so every consumer speaks the same shape instead of each re-deriving it. domain-objects
owns the pragma; it should own its parsed representation too.

---

### ask 2 — stamp the real `kind` (entity | literal) onto the pragma

the pragma carries **no** `kind`, so the consumer must decide `extends
DomainEntity<T>` vs `extends DomainLiteral<T>` by inference:

```ts
// sdk-aws-lambda: asDomainObjectPragma.ts
const kind = (pragma.primary ?? []).length > 0 ? 'entity' : 'literal';
```

the getter has `dobj` in hand and knows the subclass, so it can stamp the truth:

```js
const pragma = {
  name: dobj.name,
  kind: /* 'entity' if dobj extends DomainEntity, else 'literal' */,
  ...(dobj.primary ? { primary: dobj.primary } : {}),
  // ...
};
```

**why it matters:** the `primary`-non-empty heuristic is fragile — it equates
"declares a primary key" with "is an entity" (usually true, not type-guaranteed),
and since the pragma omits `primary` when absent, an entity declared without a
`static primary` is indistinguishable from a literal → misclassified as
`DomainLiteral` in the generated sdk (wrong base class + identity semantics).

---

### consumer compatibility

`sdk-aws-lambda` keeps its inference fallback as a graceful default: it reads
`pragma.kind` when present, else infers from `primary`. so both asks are purely
additive — no breaks; the consumer upgrades to the exact value + shared type when
they land.

### dependency

these do not gate the codegen — it ships on the local type + inference fallback.
both are correctness/ergonomics improvements to remove the heuristic and the
duplicated type. happy to align on the exact subclass-detection + the published
type's field names.
