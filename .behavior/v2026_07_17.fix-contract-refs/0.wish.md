# feat: a `refContract` getter that stamps an `x-domain-object-ref` pragma

## handoff from: sdk-aws-lambda · feat-sdk-codegen

### context

domain-objects@0.32.0 shipped `.contract` — a getter that stamps an `x-domain-object`
pragma onto a dobj's zod schema so a cross-service consumer can name, de-dupe, and
reconstruct the WHOLE dobj from the wire (composition). the sdk-aws-lambda codegen
consumes it to emit prefixed resource classes (`SvcJobsJob`, etc).

the gap: there is no way to represent a **reference** (by key) over the wire. a
contract often wants a field that references another dobj by its key, not one that
carries the whole thing:

```ts
class SurfTrophy extends DomainEntity<SurfTrophy> {
  public static schema = z.object({
    uuid: z.string(),
    rider: RefByPrimary<typeof Seaturtle>,   // just { uuid }, not the whole turtle
    board: RefByUnique<typeof Surfboard>,    // just { brand, length }
  });
}
```

today that intent has no schema representation:
- `.contract` embeds the FULL dobj (composition) — wrong for a reference.
- `refByPrimary()` / `refByUnique()` are RUNTIME instance ops (they pluck key fields
  off a live object → `{ uuid }`). they produce no schema, so no ref identity
  survives `z.toJSONSchema()`.
- `Ref<typeof X>` / `RefByPrimary<typeof X>` / `RefByUnique<typeof X>` are pure TS
  `Pick`s — erased at runtime.

so a ref field goes over the wire as a plain anonymous shape (`{ uuid: string }`)
with no hint it's a reference. the consumer can't tell "references Seaturtle by
primary" from "an inline object that happens to have a uuid".

---

### ask — publish `X.refContract('primary' | 'unique' | 'ref')`

a getter parallel to `.contract` that returns a zod schema of ONLY the referenced
key fields, stamped with an `x-domain-object-ref` pragma:

```ts
// refContract('primary') → a schema of just the primary-key fields, stamped:
Seaturtle.refContract('primary')
// ≈ z.object({ uuid: z.string() })
//     .meta({ 'x-domain-object-ref': { name: 'Seaturtle', by: 'primary' } })

// refContract('unique') → a schema of just the unique-key fields, stamped:
Surfboard.refContract('unique')
// ≈ z.object({ brand: z.string(), length: z.object({ inches: z.number() }) })
//     .meta({ 'x-domain-object-ref': { name: 'Surfboard', by: 'unique' } })

// refContract('ref') → a union of primary | unique, stamped `by: 'ref'`
Sponsor.refContract('ref')
```

pragma shape (mirrors `x-domain-object`):

```ts
interface DomainObjectRefPragma {
  name: string;                        // the referenced dobj's class name
  by: 'primary' | 'unique' | 'ref';    // which key(s) the ref carries
}
```

field-schema derivation:
- `by: 'primary'` → pick the `static primary` fields from the dobj's `static schema`.
- `by: 'unique'` → pick the `static unique` fields.
- `by: 'ref'` → a `z.union([primaryShape, uniqueShape])`.
- fail fast (like `.contract`) if the dobj has no `static schema`, or if the
  requested key (`primary`/`unique`) is not declared.

memoize per-class + per-`by` (like `contractByClass`), so repeated access is
idempotent (returns the same stamped instance).

---

### why domain-objects is the right home

- domain-objects owns `Ref` / `RefByPrimary` / `RefByUnique` (the TS types) + the
  `refByPrimary` / `refByUnique` runtime ops + the `x-domain-object` pragma. the
  ref-pragma is the schema-level sibling of all three — it belongs next to them.
- it needs the dobj's `static primary` / `static unique` / `static schema` to derive
  the key sub-shape — exactly what the class already holds.
- every consumer (not just this codegen) that wants typed references over a wire
  boundary needs the same representation; one home avoids each re-inventing it.

---

### how sdk-aws-lambda will consume it

the codegen's dobj-capture walk will read `x-domain-object-ref` off any node and
emit the matching type + import:

```ts
// generated svcSurf.resources.ts
import { DomainEntity, Ref, RefByPrimary, RefByUnique } from 'domain-objects';

export interface SvcSurfSurfTrophy {
  uuid: string;
  rider: RefByPrimary<typeof SvcSurfSeaturtle>;
  board: RefByUnique<typeof SvcSurfSurfboard>;
}
```

+ a bind check: the referenced dobj must ALSO be captured in full on some endpoint of
the same service (so `typeof SvcSurfSeaturtle` binds). if not, the codegen fails loud
and names the unbindable ref.

---

### compatibility / sequencing

- purely additive to domain-objects — a new getter + a new pragma keyword; no prior
  behavior changes.
- until it ships, sdk-aws-lambda can hand-stamp `.meta({ 'x-domain-object-ref': ... })`
  in test fixtures to build + test the codegen half, then swap to the real
  `X.refContract(...)` when it lands.
- happy to align on the getter name (`refContract` vs `refOf` vs …), the `by` values,
  and the union semantics for `'ref'`.
