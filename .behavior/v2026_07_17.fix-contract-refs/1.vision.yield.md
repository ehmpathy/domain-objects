# 1.vision — `.contract.ref(by)` for cross-service references

> illustrate the world implied by `0.wish.md`: a `.contract.ref('primary' | 'unique' | 'ref')`
> accessor — the schema-level counterpart of `.contract` — that returns a zod schema of ONLY the
> referenced key fields, stamped with an `x-domain-object-ref` pragma so a **reference** (by
> key) survives `z.toJSONSchema()` as a first-class, named artifact.

> **name decided (wisher, 2026-07-18):** the shape is **`X.contract.ref(by)`** — a `.ref`
> method hung off the extant `.contract` schema. fallback if the schema-augmentation probe fails
> is the flat **`X.contractRef(by)`**. the wish's original `refContract` is **superseded**
> (`ref`-led mis-signals a contract return; see q1).

---

## ubiqlang: `contract` vs `contract.ref`

> **`contract` carries the whole. `contract.ref` carries the key.**

| term | what it is | over-the-wire shape | consumer reads |
|---|---|---|---|
| **`Seaturtle.contract`** | the schema stamped with `x-domain-object` (full identity + keys + nested) | the WHOLE dobj shape | "this IS a Seaturtle — rebuild all of it" (composition) |
| **`Seaturtle.contract.ref('primary')`** | a schema of ONLY the primary-key fields, stamped `x-domain-object-ref` | just `{ uuid }` | "this POINTS AT a Seaturtle by primary" (reference) |

`contract.ref ⊂ contract` in payload — the ref schema is a key-only slice of the full contract,
plus a pragma that says *which dobj it references* and *by which key*. the wish draws this line
precisely: `.contract` embeds the full dobj (wrong for a field that only names another), so a
reference needs its own stamped form. the accessor nests **under** `.contract` because it *is* a
contract — a smaller, ref-flavored one — so its name should lead with the noun it extends.

three ways one dobj can appear in another's schema — this feature fills the third row:

| intent | today | representation |
|---|---|---|
| inline value object | `z.object({ ... })` | anonymous shape (fine) |
| **compose** the whole dobj | `X.contract` | `x-domain-object` pragma ✅ (shipped 0.32.0) |
| **reference** the dobj by key | `RefByPrimary<typeof X>` (TS only, erased) | `x-domain-object-ref` pragma ✅ **(this wish)** |

## the outcome world

### day-in-the-life

an upstream service (`svc-surf`) declares a contract where one dobj references another **by key**,
not by value:

```ts
class SurfTrophy extends DomainEntity<SurfTrophy> {
  public static primary = ['uuid'] as const;
  public static schema = z.object({
    uuid: z.string(),
    rider: Seaturtle.contract.ref('primary'),  // → { uuid }, stamped "references Seaturtle by primary"
    board: Surfboard.contract.ref('unique'),   // → { brand, length }, stamped "references Surfboard by unique"
  });
}
```

a downstream codegen (`sdk-aws-lambda`) converts the schema to json-schema and finds, on each
ref field, a pragma that names the target dobj and the key kind:

```jsonc
{
  "type": "object",
  "properties": {
    "uuid": { "type": "string" },
    "rider": {
      "type": "object",
      "properties": { "uuid": { "type": "string" } },
      "x-domain-object-ref": { "of": "Seaturtle", "by": "primary" }
    },
    "board": {
      "type": "object",
      "properties": {
        "brand": { "type": "string" },
        "length": { "type": "object", "properties": { "inches": { "type": "number" } } }
      },
      "x-domain-object-ref": { "of": "Surfboard", "by": "unique" }
    }
  }
}
```

from `x-domain-object-ref` alone the consumer emits the exact typed reference + import:

```ts
// generated svcSurf.resources.ts
import { DomainEntity, RefByPrimary, RefByUnique } from 'domain-objects';

export interface SvcSurfSurfTrophy {
  uuid: string;
  rider: RefByPrimary<typeof SvcSurfSeaturtle>;
  board: RefByUnique<typeof SvcSurfSurfboard>;
}
```

### before / after

| | before | after |
|---|---|---|
| a ref field over the wire | anonymous `{ uuid: string }` — indistinguishable from an inline object that happens to have a uuid | `{ uuid }` **+** `x-domain-object-ref: { of: 'Seaturtle', by: 'primary' }` |
| consumer codegen | emits a bare inline shape; loses the reference relationship | emits `RefByPrimary<typeof SvcSurfSeaturtle>` — the reference is typed and bound |
| "references X by primary" vs "an object with a uuid" | ambiguous | unambiguous — the pragma says it outright |

### the "aha"

`.contract` taught the wire to say *"I am a Seaturtle."* the aha here: teach it to also say
*"I merely point at a Seaturtle — by primary."* the same stamp-at-the-schema-boundary trick,
applied to the **reference** relationship that the TS types (`RefByPrimary<typeof X>`) already
express but that vanishes at runtime. one accessor recovers the erased intent — and it lives
right where you'd reach for it: off the `.contract` you already know.

## user experience

### usecases / goals

| persona | goal |
|---|---|
| upstream author | declare a field that references another dobj by key, inline, with identity that auto-rides to json-schema |
| downstream codegen (`sdk-aws-lambda`) | detect "this field references dobj X by key K", emit the matched `RefBy*<typeof …>` type + import + bind-check |
| library maintainer | reuse the `.contract` / `x-domain-object` mental model; the ref pragma is its schema-level kin, next to `Ref` / `refByPrimary` / `refByUnique` |

### contract inputs & outputs

- **input**: one argument `by: 'primary' | 'unique' | 'ref'`, read against the dobj's declared
  statics (`primary`, `unique`, `schema`, `name`). the `by` argument names the key kind and lands
  verbatim in the pragma's `by` field — one canonical word from call site to wire.
- **output**: a zod schema of ONLY the referenced key fields (picked from `static schema`), which
  carries `.meta({ 'x-domain-object-ref': { of, by } })`, such that `z.toJSONSchema()` emits
  the pragma verbatim.
- **pragma shape** — type `DomainObjectPragmaRef`, the partner to the merged base `DomainObjectPragma`
  (which carries `{ name, kind, primary?, unique?, alias?, nested? }`, `DomainObjectPragma.ts:48-80`).
  the ref is deliberately smaller — it points at a dobj, so it carries only which dobj + which key,
  not the full body (nor `kind`: the target's own bound `.contract` already states that — see q8):
  ```ts
  interface DomainObjectPragmaRef {
    of: string;                       // the referenced dobj's class name (constructor.name)
    by: 'primary' | 'unique' | 'ref'; // which key(s) the ref carries
  }
  ```

### what use looks like

```ts
// pick a key kind off the contract, get back a stamped, embeddable zod schema
Seaturtle.contract.ref('primary')  // z.object({ uuid: z.string() }).meta({ 'x-domain-object-ref': { of: 'Seaturtle', by: 'primary' } })
Surfboard.contract.ref('unique')   // z.object({ brand, length }).meta({ 'x-domain-object-ref': { of: 'Surfboard', by: 'unique' } })
Sponsor.contract.ref('ref')        // z.union([primaryShape, uniqueShape]).meta({ 'x-domain-object-ref': { of: 'Sponsor', by: 'ref' } })

// embed inline, exactly like .contract
const schema = z.object({ rider: Seaturtle.contract.ref('primary') });
const json = z.toJSONSchema(schema); // json.properties.rider['x-domain-object-ref'] present
```

### timeline

1. author declares dobjs with `primary` / `unique` / `schema` (already there).
2. at a field that references another dobj, they write `X.contract.ref('primary')` instead of a
   hand-declared key shape.
3. codegen converts to json-schema → `x-domain-object-ref` present on the field.
4. consumer reads the pragma → emits `RefBy*<typeof PrefixedX>` + import + bind-check.

## mental model

- **how a user describes it to a friend**: "instead of the whole turtle in the box, I clip on a
  little claim ticket that says *'turtle #821, look it up by its uuid'*. the other service reads
  the ticket and knows it's a pointer, not the turtle."
- **analogy**: `.contract` is the whole book; `.contract.ref` is the ISBN. the ISBN is enough to
  name the book and look it up — you don't re-print the book to reference it. and you find the ISBN
  *on* the book (`.contract.ref` hangs off `.contract`), not in a separate catalog.
- **precedent chain**: `_dobj` (serialize string) → `x-domain-object` (full contract, json-schema)
  → `x-domain-object-ref` (reference, json-schema). same "stamp identity onto the serialized
  form" idea, now for the *reference* relationship.

| they say | we say |
|---|---|
| "claim ticket / pointer / ISBN" | `x-domain-object-ref` pragma |
| "look it up by its id" | `by: 'primary'` |
| "look it up by its natural key" | `by: 'unique'` |
| "either key works" | `by: 'ref'` → `z.union([primary, unique])` |

## evaluation

### how well it solves the goals

- **represents a reference over the wire**: ✅ `x-domain-object-ref` names the target + key kind.
- **distinguishes ref from inline shape**: ✅ the pragma is the discriminator the consumer needs.
- **reuses extant statics**: ✅ derives the key sub-shape from `primary` / `unique` + `schema`.
- **discoverable**: ✅ hangs off `.contract`, so `X.contract.` autocomplete reveals `.ref` next to
  the contract the author already reaches for — noun-first order (`rule.require.order.noun_adj`).
- **purely additive**: ✅ a `.ref` method on the returned contract + a new pragma keyword; no change
  to `.contract`'s own return value or prior behavior.

### pros

- authors no longer hand-write key shapes for ref fields — derive once from the source of truth.
- one consistent stamp family (`_dobj` / `x-domain-object` / `x-domain-object-ref`).
- non-mutative + memoized (per-class **and** per-`by`), like `contractByClass`.
- consumer gets a typed, bindable reference instead of an anonymous shape.
- the name tells the truth about the return type — it comes off `.contract`, so it returns a
  contract (a stamped schema), not a runtime ref (unlike `refByPrimary`, which returns a plucked
  `{ uuid }`).

### cons / costs

- same **zod-4-only** tie as `.contract` (needs `.meta()` + `z.toJSONSchema`); joi/yup fail fast.
- adds a second custom json-schema keyword the consumer must know (`x-domain-object-ref`).
- requires `static schema` to be a **zod object** to `.pick()` the key fields — a schema that
  isn't object-shaped can't be sliced (fail-fast, see edgecases).
- the memo key is now a pair (`class` + `by`) — three stamped variants per class, not one.
- **`.contract` must grow a `.ref` method** — a function property hung on the returned zod schema.
  novel for this lib, and fragile across derived schemas (see awkward §4 + q5 probe).

### `.contract.ref(by)` access contract — fail-fast

> to get a `.contract.ref(...)`, the dobj must declare a **zod object** `static schema` **and** the
> requested key.

mirrors `.contract`'s strictness; fail loud at access, never a silent pragma-absent bug downstream.

| access condition | behavior |
|---|---|
| no `static schema` | **`ConstraintError`** (caller-fix): "`.contract` requires a `static schema`" (thrown by `.contract` itself, before `.ref`) |
| schema not zod (joi/yup) | **`ConstraintError`**: "requires a **zod** schema" (thrown by `.contract`) |
| schema not object-shaped (can't `.pick`) | **`ConstraintError`**: "`.contract.ref` requires an object schema to derive key fields" |
| `by: 'primary'` but no `static primary` declared | **`ConstraintError`**: "`.contract.ref('primary')` requires `static primary` on X" |
| `by: 'unique'` but no `static unique` declared | **`ConstraintError`**: "`.contract.ref('unique')` requires `static unique` on X" |
| `by: 'ref'` but neither key declared | **`ConstraintError`**: needs at least one of primary/unique |
| a declared key names a field absent from the schema | **`ConstraintError`**: key/schema mismatch (fail loud, don't pick a hole) |

### edgecases & pit-of-success

| edgecase | pit-of-success contract |
|---|---|
| repeated access | memoize per `class`+`by` → same stamped instance back (idempotent) |
| author mutates the returned schema | `.meta()` returns a fresh schema; memo keeps it stable |
| a **derived** contract (`X.contract.optional().ref(...)`) | **open** — zod's `.optional()` returns a fresh instance without our `.ref` method; only `X.contract.ref(...)` off the raw contract works (see awkward §4 + q5) |
| `by: 'ref'` with only one key declared | union-of-one degrades to the single declared key (see q3) |
| a **unique key that is itself a dobj** (e.g. `unique = ['turtle']`) | **recurse to match runtime** (wisher, q2) — the nested dobj key derives its *own* `.contract.ref('unique')` sub-shape, so the schema mirrors what `refByUnique` produces (not the nested dobj's full shape) |
| consumer on zod 3 | pragma is plain json — readable without zod, like `x-domain-object` |

## open questions & assumptions

### assumptions

1. the pragma is deliberately **smaller** than `x-domain-object` — a reference needs only
   `{ of, by }` (which dobj + which key), not `primary`/`unique`/`alias`/`nested`. the consumer
   binds to the full contract elsewhere for those. (wish stated `{ name, by }`; wisher renamed
   `name` → `of` — see q1 — since a ref *points at* a dobj rather than *is* one.)
2. zod-4 baseline is already the lib's reality (`.contract` shipped on it) — no new dependency cost.
3. `static schema` is a `z.object(...)` for any dobj that wants a `.contract.ref` (needs `.pick`).
4. `constructor.name` is a stable identity carrier — same assumption `.contract` + `_dobj` rely on
   (minification risk noted there applies equally here; mitigate via un-mangled class names).
5. downstream tools preserve unknown `x-` keywords — confirmed for the `sdk-aws-lambda` pipeline
   in the `.contract` vision; the same pipeline consumes this pragma.

### open questions (triaged)

each tagged `[answered]` (decided now), `[research]` (answer in research/execution), or
`[wisher]` (needs wisher/consumer input).

1. **`[answered]` accessor shape → `X.contract.ref(by)`.** wisher decided (2026-07-18).
   - **why `.contract.ref` over `refContract`**: it returns a **contract** (a stamped zod schema),
     not a ref. `refByPrimary(instance)` correctly leads with `ref` because it *returns a ref* (a
     plucked `{ uuid }`); this returns a contract, so a lead with `ref` mis-signals the return
     type. to nest under `.contract` is noun-first (`rule.require.order.noun_adj`): the head noun
     leads, and `X.contract.` autocomplete groups `.ref` with the contract it extends.
   - **why a method under `.contract`, not a top-level getter**: `.contract` is a zero-arg getter;
     the ref needs an argument (`by`), so it cannot itself be a getter. to hang `.ref(by)` off
     the returned schema keeps the noun-first order and reads as prose ("the contract's ref, by
     key").
   - **fallback → `X.contractRef(by)`**: same contract-led, noun-first order as a flat method,
     with zero schema-augmentation risk. adopt this if the q5 schema-augmentation probe fails.
   - **superseded → `refContract` / `refOf`**: `refContract` mis-signals return type (above);
     `refOf` overlaps the runtime `refByPrimary` "ref of an instance" sense.
   - **arg named `by`** (wisher, 2026-07-18): the accessor arg reuses the pragma's `by` word, so one
     canonical term runs from call site (`.ref('primary')`) to wire (`{ by: 'primary' }`) — no
     `grain`/`by` synonym drift (`rule.require.ubiqlang`).
   - **pragma type → `DomainObjectPragmaRef`; field `of` not `name`** (wisher, 2026-07-19):
     - **field `of` over `name`**: in the full pragma, `name` is *reflexive* ("I **am** a Seaturtle").
       in a ref it is *relational* ("I **point at** Seaturtle") — the same word would overload two
       senses (`rule.forbid.term.addition.ambiguous`). `of` pairs with `by` as a phrase: "a ref
       **of** Seaturtle **by** primary", echoing the vision's own prose. this diverges from the
       wish's verbatim `{ name, by }`, but the divergence is earned by the semantic difference.
     - **type `DomainObjectPragmaRef` over `DomainObjectRefStatics` / `...Pragma`**: the payload is
       **not** statics — `of` derives from a static (`.name`) but `by` is a choice at the reference
       site (which key-set to project), so a `...Statics` suffix would misname it. the shared concept
       is the **pragma** (the stamped annotation): base `DomainObjectPragma` (the full `x-domain-object`
       payload) and `DomainObjectPragmaRef` (the `x-domain-object-ref` payload). this mirrors the
       accessor shape exactly — `.contract` → `DomainObjectPragma`, `.contract.ref` →
       `DomainObjectPragmaRef`. **confirmed by the merged peer** (#131, 2026-07-21): the base shipped
       as `DomainObjectPragma` (`src/manipulation/DomainObjectPragma.ts`) and its type doc
       **reserves `DomainObjectPragmaRef`** for this wish — "a peer-branch partner, not yet exported"
       (`DomainObjectPragma.ts:28-35`). the base + `Ref` pair mirrors the runtime `DomainObject : Ref`
       pair. so both names are now settled cross-team, not just proposed.
     - **avoided → `DomainRef*`**: `DomainRef` is a **dropped** prefix — the standardize wish chose
       "`Ref` instead of `DomainReference`" (`.behavior/v2025_11_23.standardize/0.wish.md:8`); only
       stale docstrings/test-describes still say `DomainRef*` (`RefByPrimary.ts:27`, `.test.ts:33`).
       reusing it would resurrect deprecated vocab.
2. **`[answered]` `by: 'unique'` when a unique key is a nested dobj → recurse (match runtime).**
   wisher decided (2026-07-18). `refByUnique` recursively reduces a nested dobj key to the nested
   dobj's *own* unique ref (`refByUnique.ts:56-61`); the derived schema must mirror that. so when a
   `unique` key names a nested dobj, `.contract.ref('unique')` derives that field's sub-shape via the
   nested dobj's *own* `.contract.ref('unique')` (recursion), **not** a raw `.pick` of the nested
   dobj's full shape. this keeps the wire schema and the runtime `refByUnique` value in agreement —
   no schema/runtime drift. execution note: the recursion terminates at the first non-dobj key field;
   guard against a cyclic unique-key graph (fail loud if one exists).
3. **`[answered]` `by: 'ref'` union *mechanics*.** decidable now by logic: (a) a union-of-one
   degrades to the single declared key (no empty union); (b) the union carries ONE top-level
   `x-domain-object-ref` stamp with `by: 'ref'` — the arms are not stamped one-by-one (the consumer
   reads one field, one pragma). wish says `z.union([primaryShape, uniqueShape])`; these are the
   least-surprise mechanics that satisfy it. *(whether `'ref'` ships now vs defers is scope, q6.)*
4. **`[answered]` should `DomainObjectPragmaRef` be an exported type? → yes.** decidable by logic:
   a consumer that reads the pragma needs a type to read it against, and `src/index.ts` exports the
   dobj surface, so the ref pragma type belongs there too. *(the peer coordination — alignment of
   the base pragma type name with the `kind` handoff — is the `[wisher]`/cross-team half, q7.)*
5. **`[research]` two zod-v4 probes, both must pass with a real call before execution:**
   - (a) **derivation passthrough**: does `ZodObject.pick(...)` preserve a `.meta()` stamp through
     `z.toJSONSchema()`, and does `z.union(...).meta(...)` emit `x-domain-object-ref` at the `anyOf`
     level verbatim? the `.contract` path proved only the `z.object().meta()` shape round-trips.
   - (b) **schema-augmentation feasibility** (new, gates the `.contract.ref` shape): can we hang a
     `.ref` method on the memoized `.contract` schema (e.g. `Object.assign`) such that
     `z.toJSONSchema(X.contract)` does **not** leak the `.ref` function into output, and inline
     embed (`z.object({ rider: X.contract.ref('primary') })`) still round-trips? if (b) fails,
     fall back to the flat `X.contractRef(by)` per q1.
6. **`[answered]` should `'ref'` ship now? → yes, ship all three (`primary`, `unique`, `ref`).**
   wisher decided (2026-07-18): ship-for-symmetry. all three `by` values land together so the
   accessor fully parallels the `Ref` / `RefByPrimary` / `RefByUnique` type family — `'ref'` (the
   union) is a first-class `by`, not a deferred add-on. no partial API.
7. **`[answered]` align pragma type names with the `kind` peer handoff → resolved by the merge.**
   the peer handoff shipped and merged to main as **#131** (`fix(contract): publish DomainObjectPragma
   type + stamp kind onto the .contract pragma`). it landed the base type as **`DomainObjectPragma`**
   (this wish's proposed name, not the earlier `DomainObjectStatics`) and its type doc **reserves
   `DomainObjectPragmaRef`** for us (`DomainObjectPragma.ts:28-35`). so the cross-team question is
   settled in our favor — no unilateral rename needed, the base is already `DomainObjectPragma` on
   main, and `DomainObjectPragmaRef` is the agreed partner name to add here.
8. **`[answered]` should the ref pragma carry the new `kind` field? → no, stay `{ of, by }`.**
   the peer merge (#131) grew the *full* pragma a `kind` field (`'entity'|'literal'|'event'|'object'`
   via `getKind`, `getContract.ts:88-95`) so a consumer picks the right base class to rebuild the
   whole dobj. a **reference** does not rebuild the target — it points at it, and the target's own
   full `.contract` (bound elsewhere via the codegen bind-check) already carries `kind`. so the ref
   stays minimal: `of` (which dobj) + `by` (which key). adding `kind` would duplicate what the bound
   full contract already states. decidable by logic — the ref's job is to identify, not reconstruct.

## groundwork

sanity check — enough to know the vision isn't built on false assumptions; not exhaustive.

### external research

the wish references zod's `z.toJSONSchema()`, `.meta()`, and (implicitly) `.pick()` / `z.union()`.

- **verified**: `.contract` already ships on this exact zod-4 stack — `getContract.ts:98` stamps
  via `schema.meta({ 'x-domain-object': pragma })` and `getContract.test.ts:18` round-trips it
  through `z.toJSONSchema()`. the `.meta()` + `toJSONSchema` passthrough for a custom keyword is
  **proven in-repo**, so the ref pragma rides the same proven path.
- **verified**: installed zod is **4.4.3** (`node_modules/zod/package.json:3`) and the repo declares
  `"zod": "^4.4.3"` (`package.json:108`) — the zod-4 baseline is fact, not assumption.
- **not yet verified** (flagged q5 for execution): (a) that `ZodObject.pick(...)` and `z.union(...)`
  both preserve a `.meta()` stamp through `z.toJSONSchema()`; (b) that a `.ref` method hung on the
  `.contract` schema does not leak into `z.toJSONSchema()` output. the apis exist; both must be
  proven with a real call, not assumed.
- no other external APIs/services referenced.

### internal research

the wish references `.contract`, the `x-domain-object` pragma, and `Ref`/`refByPrimary`/`refByUnique`.

- **stdouts**: none — this is a library-surface feature, no CLI output/error formats.

## what is awkward?

1. **the recursion for unique-key-is-a-dobj (decided q2, but intricate).** the fork is settled —
   `.contract.ref('unique')` recurses to match `refByUnique`'s runtime output rather than raw-pick
   the nested dobj's full shape. what remains awkward is the *implementation depth*: the derivation
   is no longer a flat `.pick`, it must walk nested dobj keys and re-derive each via its own
   `.contract.ref('unique')`, terminate at non-dobj fields, and guard against a cyclic unique-key
   graph. more surface to get right than `'primary'` (which stays a flat pick), but the payoff is
   zero schema/runtime drift.

2. **two custom keywords now.** consumers must know both `x-domain-object` (full) and
   `x-domain-object-ref` (reference). a small private standard grows a second term; fine for the
   domain-objects ↔ sdk-aws-lambda pair, but it's a link both sides must track.

3. **`by: 'ref'` is a shape-shifter.** `'primary'`/`'unique'` return a `z.object`; `'ref'` returns
   a `z.union`. one accessor with two output kinds (object vs union/anyOf) is slightly awkward for a
   consumer to branch on — though the `by` field in the pragma tells them which to expect.

4. **`.contract` becomes a namespace — a method on a schema.** to get `X.contract.ref(...)` we hang
   a `.ref` function on the returned zod schema. two frictions follow: (a) it's a novel pattern for
   this lib — a reviewer may ask "why does a schema have methods" (defensible: `.contract` is
   already *our* augmented schema, not a raw one); (b) it's fragile across derived schemas —
   `X.contract.optional().ref(...)` fails because zod's `.optional()` returns a fresh instance
   without our `.ref`. only `X.contract.ref(...)` off the raw contract works; must document. if the
   q5(b) probe shows this is unsafe, fall back to the flat `X.contractRef(by)`.

5. **`static schema` must be object-shaped to slice.** `.contract` accepts any zod schema;
   `.contract.ref` additionally needs a `z.object` to `.pick()` keys from. a dobj with a
   non-object schema can hold a `.contract` but not a `.contract.ref` — a subtle capability gap
   between the full contract and its ref.

6. **hand-typed today, derived tomorrow — but only where a dobj already declares the key.** the
   ergonomic win (no longer re-declare key shapes) only lands for dobjs that declare
   `primary`/`unique`. a dobj referenced by a key it doesn't formally declare can't produce a
   `.contract.ref` — correct, but it means the feature quietly requires disciplined key declaration
   to pay off.
