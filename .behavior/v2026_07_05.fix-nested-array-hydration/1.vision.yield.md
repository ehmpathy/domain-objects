# vision — fix nested array hydration for bare scalars

fulfills ehmpathy/domain-objects#123

## the outcome world

### day-in-the-life

a developer models a domain object with a nested union key. one key can hold a
bare scalar, a bare array of scalars, or a wrapper object — all without writing a
custom constructor. they instantiate the object and every shape round-trips
exactly as declared.

the test-drive uses a seaturtle-themed model (per wisher). a `Seaturtle` forages
via an `include` or `exclude` selector — the bare shorthand names a single food
or a list; the wrapper form declares an include/exclude policy (the ergonomic
analogue of aws iam `Resource` vs `NotResource`).

```ts
interface SeaturtleForage {
  include?: string;
  exclude?: string;
}
class SeaturtleForage
  extends DomainObject<SeaturtleForage>
  implements SeaturtleForage {}

interface Seaturtle {
  forage: string | string[] | SeaturtleForage;
}
class Seaturtle extends DomainObject<Seaturtle> implements Seaturtle {
  public static nested = { forage: SeaturtleForage };
}

new Seaturtle({ forage: 'seagrass' });                  // stays 'seagrass'
new Seaturtle({ forage: ['seagrass', 'jellyfish'] });   // stays ['seagrass','jellyfish']  ← the fix
new Seaturtle({ forage: { include: 'seagrass' } });     // SeaturtleForage instance
new Seaturtle({ forage: { exclude: 'jellyfish' } });    // SeaturtleForage instance
```

### before / after

| input on a single-option nested key | before | after |
|-------------------------------------|--------|-------|
| `forage: 'seagrass'` (bare scalar)  | `'seagrass'` (field-level skip) | `'seagrass'` (unchanged) |
| `forage: ['seagrass','jellyfish']` (bare array) | `[SeaturtleForage('seagrass'), SeaturtleForage('jellyfish')]` — **corrupted** | `['seagrass','jellyfish']` (element-level skip) |
| `forage: { include: 'seagrass' }` (object) | `SeaturtleForage` instance | `SeaturtleForage` instance (unchanged) |

### the "aha"

a bare string behaves the **same** whether or not it sits inside an array.
today it silently mutates based only on its position. after the fix, hydration is
for objects — never for primitives — at every level.

## user experience

- **usecase**: model a nested field as `scalar | scalar[] | Wrapper{...}` on one
  key, no custom constructor. the bare form is the ergonomic shorthand; the object
  form maps to richer structure (e.g. aws iam `Resource` vs `NotResource`).
- **contract inputs**: `static nested = { key: SomeDomainObject }` plus a props
  value that is a bare scalar, a bare array, or an object.
- **contract outputs**: instantiated domain object where bare scalars/arrays pass
  through untouched and objects hydrate into the declared class.
- **timeline**: declare class → instantiate with any of the three shapes → read
  back the value in the exact shape supplied.

## mental model

- to a friend: "domain-objects only wraps objects into classes; it leaves plain
  strings and numbers alone — now even when they're inside a list."
- analogy: a coat-check that only takes coats. before, if you handed it a bag of
  loose strings it tried to hang each string on a hanger. now it hands the bag back.
- terms **users** use: nested field, bare value, array shorthand, wrapper.
- terms **we** use: field-level guard, element-level guard, hydration, scalar skip,
  `instantiateThisPropIfNeeded`.

## evaluation

- **solves the goal**: yes — restores symmetry between field-level and
  element-level scalar handling. unlocks the union-on-one-key shorthand.
- **pros**: one-line guard mirrors a prior, proven guard; no new api; no config;
  fixes a silent data-corruption bug.
- **cons**: none material. it is strictly more permissive — a shape that used to
  corrupt now passes through. no shape that used to hydrate correctly changes.
- **edgecases & pit-of-success**:
  - `forage: [{...}, {...}]` — array of objects → still hydrates each (objects, not
    scalars). unchanged.
  - `forage: ['seagrass', { include: 'jellyfish' }]` — mixed array → scalar stays,
    object hydrates. consistent element-level rule.
  - `forage: [null]` — null element passes through (matches `null === null` guard).
    note: this null-in-array case is inferred, not stated by the wisher — treated as
    a consistency check, not a mandate (see r3 assumptions review).
  - multi-option nested keys (`[A, B]`) — a bare scalar element can't carry a `_dobj`
    hint, so it now passes through instead of throwing. this matches field-level
    behavior for scalars and is the intended, consistent outcome.

## groundwork

### external research

none — no external dependencies. the consuming context (declastruct-aws iam
policy modeling) is motivation only; this change lives entirely inside
domain-objects.

### internal research

- **contract to conform to** — field-level guard already present:
  `src/instantiation/hydrate/hydrateNestedDomainObjects.ts:51-52`
  ```ts
  const nestedProp = props[key];
  if (typeof nestedProp !== 'object' || nestedProp === null) return;
  ```
- **fix location** — `instantiateThisPropIfNeeded` at
  `src/instantiation/hydrate/hydrateNestedDomainObjects.ts:59`. it has no
  bare-value guard at its top; the single-option branch at line 73-74 calls
  `.build(prop)` on whatever it receives, including scalars.
- **array dispatch** — `hydrateNestedDomainObjects.ts:131-133` maps each element
  through `instantiateThisPropIfNeeded`. a bare array like `['a','b']` passes the
  field-level guard (arrays are objects) then corrupts element-by-element.
- **note on real vs issue snippet**: source wraps via `.build(prop)` (line 74),
  not `new Class(prop)`. the issue snippet is illustrative; the asymmetry and fix
  are as described.
- **test patterns to match** —
  `src/instantiation/DomainObject.test.ts:201-303` uses `describe('hydration')`,
  jest `it('should ...')`, and covers nested single, nested array, nullable-null,
  and multi-option-with-`_dobj`. new tests slot in beside these with the same
  structure.
- **test vocab (per wisher)** — the extant tests use `PlantPot`/`PlantOwner`/
  `PlantBed`, but the wisher directed a **seaturtle-themed** example for the new
  tests. use `Seaturtle` with `static nested = { forage: SeaturtleForage }` and
  `SeaturtleForage { include?, exclude? }`. cover the four shapes on the one
  `forage` key: bare scalar, bare array, `{ include }`, `{ exclude }`.

## what is awkward?

- multi-option nested keys with a bare scalar element: pre-fix this throws a
  "can't determine which option" error; post-fix it passes through silently. that
  is the correct, consistent behavior (scalars are never hydrated), but it does
  quietly change one error path into a pass-through. worth an explicit test so the
  behavior is documented, not incidental.
- no other friction. the change is a single guard clause mirroring a prior one.
