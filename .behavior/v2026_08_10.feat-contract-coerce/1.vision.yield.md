# 1.vision — `.contract()`: the boundary that hands back the domain object

> the wish: give a dobj's `.contract` a coerced form — one that parses a plain wire payload into a
> real dobj instance, typed as the class, with a constructor failure contained as a zod issue.
>
> **the settled answer is smaller than the ask.** there is no `.coerce()` method. `.contract` becomes
> a **call**, the call **is** the boundary, and a boundary always hands back the domain object. two
> forms ship where three were drawn.

---

## 1. the outcome world

### day in the life

kai writes a lambda that books a surf lesson. the input arrives as json over the wire.

**before** — the schema validates, then kai rebuilds the graph by hand:

```ts
const schema = z.object({
  surfer: Surfer.contract,
  spot: SurfSpot.contract.nullable(),
  boards: z.array(Surfboard.contract),
});

const handle = async (event: z.infer<typeof schema>) => {
  // `event.surfer` is typed `any` — the compiler has no say here
  return genSurfLesson({
    surfer: new Surfer(event.surfer),
    spot: event.spot ? new SurfSpot(event.spot) : null,
    boards: event.boards.map((board) => new Surfboard(board)),
  });
};
```

three constructors, a `.map`, a ternary. each must be revisited when a field moves. none is
compiler-checked, because `.contract` erases to `any`. the tired author reaches for
`event as Surfer` instead — the cast `rule.forbid.as-cast` already blocks.

**after** — one pair of parens carries the whole promise:

```ts
const schema = z.object({
  surfer: Surfer.contract(),
  spot: SurfSpot.contract().nullable(),
  boards: z.array(Surfboard.contract()),
});

const handle = async (event: z.infer<typeof schema>) => {
  // `event.surfer` is a `Surfer`. `event.boards` is `Surfboard[]`. the compiler agrees.
  return genSurfLesson(event);
};
```

the rebuild block is gone. so is the cast temptation. and the **declarations** of `Surfer` /
`SurfSpot` / `Surfboard` do not change at all — no opt-in line, no new base class.

### the before/after contrast

| | before | after |
|---|---|---|
| what a parse yields | a plain object | a dobj instance |
| what `z.infer` says | `any` | the class |
| a wrong shape at the call site | compiles | fails to compile |
| ceremony per dobj field | a constructor call | none |
| where the knowledge lives | every handler | the schema position |
| what a dobj declaration must add | — | **none** |

### the aha

> **a contract is not a description of a boundary. it IS the boundary.** so it always hands back the
> domain object, and it always accepts the wire — because that is what a crossed boundary means.

one position states both halves at once. the wire shape, the runtime class, and the emitted
json-schema all follow from it, with no second place to keep in sync.

## 2. the shape

### the shipped surface — two forms, both typed

```ts
X.contract                     // ⛔ REMOVED as a schema — a plain function (f10)
X.contract()                   // → ZodType<WithImmute<X>, X>   the boundary. coerces. memoized.
X.contract().ref()             // → ZodType<Ref<X>>             the union of the key refs
X.contract().ref('primary')    // → ZodType<{ uuid: string }>
X.contract().ref('unique')     // → ZodType<{ name: string }>
```

no form hands back `any`. the type:

```ts
// the bare property: callable, and no other face
interface DomainObjectContract {
  <TClass extends Refable<any, any, any>>(this: TClass): ContractOf<TClass>;
}

// what the call yields: the boundary codec, plus the ref ops
interface ContractOf<TClass extends Refable<any, any, any>>
  extends ZodType<WithImmute<InstanceType<TClass>>, InstanceType<TClass>> {
  ref(): ZodType<Ref<TClass>>;
  ref(by: 'primary'): ZodType<RefByPrimary<TClass>>;
  ref(by: 'unique'): ZodType<RefByUnique<TClass>>;
}
```

three properties of that declaration are load-critical:

- **the call captures `TClass`, not `TInstance`.** `RefByPrimary<T>` resolves through `T['primary']`
  — a **static**. from an instance type alone a "ref" degrades to every field at once, which is the
  whole object rather than a reference to it (g24b)
- **the out-type is `WithImmute<X>`.** construct via `X.build(props)`, so the root carries `.clone`
  exactly as its own nested values already do (`hydrateNestedDomainObjects` builds every nested
  value with `ClassOption.build`)
- **the in-type is the plain `X` interface**, which a bare json literal satisfies structurally (a2)

### why a call — the one hard constraint

`contract` is a **static getter** (`DomainObject.ts:114`), so its type is looked up on
`typeof DomainObject`'s static side, where no member can mention the subclass — the limit this repo
already records at `DomainObject.ts:93`.

compiled, each with a negative control (g9, g22b):

| shape | result |
|---|---|
| static getter → a type built from `InstanceType<typeof this>` | binds to the **host** class ❌ |
| static getter that declares a `this` **type** | `TS2526` — banned in a static ❌ |
| base declares a static from its own class param | `TS2302` ❌ |
| **a method with a `this` param, reached by property** (`X.contract.coerce()`) | **`TS2684`** ❌ |
| **a method with a `this` param, reached by a CALL** (`X.contract()`) | ✅ the **subclass** |

> **typescript carries a subclass's identity through a CALL, never through a property access.**

that law is enbriefed (`define.subclass-identity-needs-a-call`), because it outlives this feature.
it is also why `.ref` used to survive a property chain: it returned `ZodSchema<any>`, so it asked
none of the class. the parens are **forced by the language**, not chosen — `X.contract.coerce()` is
unreachable at any effort.

### why the call always coerces — and why there is no `.coerce()`

the wish drew three forms (bare / plain-call / coerced-call). two of the three do not survive:

- **the bare property is removed** (f10) — same runtime value, strictly worse type. it was the form
  autocomplete offers first, so it was a trap
- **a separate plain call is unneeded** (f2/f7) — the case it existed for was an *output* position,
  and that case was measured away:

| the worry | measured |
|---|---|
| an output position would emit the wrong direction | ❌ an instance and its plain form stringify **byte-identically** at depth 3; `.clone` is a function, so `JSON.stringify` skips it (g29, g39) |
| a decode on an already-hydrated value would corrupt | ❌ **idempotent** — instance in, equal instance out, at a cost of one extra ctor per response (g41d) |
| the round trip would be lossy | ❌ **identity** at depth 3, byte for byte (g41a) |

so one word serves every boundary, in both directions. that is what makes the surface two forms
rather than three, and it is the wisher's call on f2.

### it is a `z.codec`, by structure

zod's codec contract is *serialized ⇄ rich runtime*, asserted by a round trip. a dobj boundary is
that shape unmodified:

| codec | side A (wire) | side B (runtime) |
|---|---|---|
| `isoDatetimeToDate` | `"2024-01-15T10:30:00Z"` | `Date` |
| `jsonCodec` | `'{"name":"Alice"}'` | the parsed object |
| **`X.contract()`** | `{ name, spot: {…} }` | a `Surfer` |

its two halves already have names in this repo: **decode = hydrate** (`X.build` +
`hydrateNestedDomainObjects`), **encode = serialize**. a `.transform()` could express only half, and
throws on `z.encode` (`ZodEncodeError`). measured identical on hydration, guard behavior, and
pragma — plus a live encode (g25, g28).

**the round-trip obligation, measured** (g41):

| | result |
|---|---|
| `encode(decode(wire))` at depth 3 | ✅ **byte-identical**; no `.clone` leak at any level |
| a schema with a `.default()` | ⚠️ a stable **superset** — `{name}` → `{name, level:'beginner'}` |
| encode via this repo's own `serialize` | ✅ the `_dobj` stamp **never reaches the wire** — the encode is piped back through the contract, a `z.object`, which strips the unknown key |

the `.default()` case is not a defect — a default fills a key the wire omitted, so the decoded value
legitimately carries more. it is stable (a second trip is a fixpoint). the readme owes the sentence.

### the runtime — a plain function

`contract` is a **plain function**. it returns the memoized boundary codec.

```
typeof             → 'function'
instanceof ZodType → false        ← it is NOT a schema, deliberately
called             → a real zod schema; parses, chains, emits
```

that `false` is the win. an earlier design kept the bare property alive as a schema for backcompat,
which forced a **bridge** — a function re-prototyped onto a schema. it worked, but only because zod
identifies a schema by its prototype chain, an undocumented internal. removal deleted it, and
removal is strictly better on the axis that matters (g34):

| | plain function (shipped) | the bridge (obsolete) |
|---|---|---|
| `z.object({ x: <it> }).parse(…)` | ✅ **throws** — *"expected a Zod schema"* | ❌ **parses fine — the footgun succeeds** |
| rests on a zod internal | **no** | yes |

**no zod internals ship.** that was the largest open risk in the proposal, and it left with the bare
property.

### the two contractual concerns

instantiation and introspection, from one declaration — see `define.contract-usecases` for the full
law. the short form:

| | **in** side (wire json) | **out** side (domain instance) |
|---|---|---|
| **describe** it | `z.toJSONSchema(s, { io: 'input' })` → the wire shape **+ the pragma** ✅ | `z.toJSONSchema(s, { io: 'output' })` → ❌ throws; a class is not json |
| **produce** it | `z.encode(s, instance)` → the wire props | `s.parse(wire)` → a dobj instance |

verified from a **single** schema object (g31): `publishedIsWireShape: true`,
`publishedHasPragma: true`, `parsedIsInstance: true`, `nestedIsInstance: true`.

⚠️ **the `io: 'output'` throw is accurate, not a defect.** `'output'` asks what a parse hands back,
and a coerce exists precisely to hand back a value that is not json. any design that satisfied it
would have stopped to yield an instance — g26 row 1 demonstrates exactly that: an out-side that is a
real object schema emits **by destruction of the instance**.

⚠️ **the pragma lives on the IN side** (g30d), so `{ io: 'input' }` is correct on two independent
grounds — the only face that emits, and the only face that carries the pragma.

### ⚠️ "input" does double duty — and this is where an adopter will slip

the word is overloaded across two levels, and the two do **not** line up:

| the word | scope | values |
|---|---|---|
| **border** | the **endpoint** — which way a message travels | request (`input`) / response (`output`) |
| **side** | the **contract** — which face of the codec | wire (`in`) / instance (`out`) |

> **`io` names the SIDE of the contract. it never names the BORDER of the endpoint.**

so an endpoint that declares both borders emits **both** with `{ io: 'input' }`:

```ts
const contract = {
  input:  z.object({
    surfer:    Surfer.contract().ref(),
    surfboard: Surfboard.contract(),
  }),
  output: z.object({
    reservation: SurfboardReservation.contract(),
  }),
};

z.toJSONSchema(contract.input,  { io: 'input' });   // ✅ what the CALLER supplies
z.toJSONSchema(contract.output, { io: 'input' });   // ✅ what the ENDPOINT supplies back
```

| border | whose value crosses | `{ io: 'input' }` describes |
|---|---|---|
| **input** (request) | the caller's | what a caller must send |
| **output** (response) | the endpoint's | what the endpoint hands back |

**the trap**: `{ io: 'output' }` on the **output** border reads natural and is wrong. it asks for the
*contract's* out side — the hydrated instance — which is not json, so the emit **throws**. the
symmetry the eye expects does not exist, because the two words are about different levels.

so the rule is blunt, which is what makes it safe to hold:

> **every emit, at every border, passes `{ io: 'input' }`.** unconditionally. there is no position
> where the other value is correct.

that bluntness is why the flag belongs in an sdk's emit helper as one line rather than a per-schema
judgment — and it is safe even on a position with no codec, where the two faces differ by exactly
one key (g31b).

## 3. user experience

### the usecases

| # | goal | what the author writes |
|---|---|---|
| u1 | receive a dobj at a service boundary | `z.object({ surfer: Surfer.contract() })` |
| u2 | an optional / nullable dobj field | `Surfer.contract().nullable()` |
| u3 | a list of dobjs | `z.array(Surfboard.contract())` |
| u4 | **return** a dobj from a handler | `Surfer.contract()` — the same declaration |
| u5 | reference a dobj by key, not compose it | `Surfer.contract().ref('primary')` |
| u6 | publish the wire contract for codegen | `z.toJSONSchema(schema, { io: 'input' })` |

### the contract inputs & outputs

| face | shape |
|---|---|
| `z.input` at the position | the plain wire shape (a json literal satisfies it) |
| `z.output` / `z.infer` | `WithImmute<X>` — the instance, plus `.clone` |
| on a valid parse | `instanceof X`, with `X.nested` hydrated **all the way down** |
| on a schema miss | an ordinary zod issue, on the field path |
| on a **constructor** failure | a `custom` zod issue on the field path — never a throw |
| `z.toJSONSchema(…, { io: 'input' })` | the plain object schema, `x-domain-object` pragma intact |
| `z.toJSONSchema(…)` (default `io`) | **throws** — pass `{ io: 'input' }` |
| `z.encode(schema, instance)` | the plain wire props |

### the guard's message must name the fix

a naive transform lets a constructor throw escape `safeParse` entirely (g4) — which matters because
callers branch on `if (!result.success)`, and a throw skips that branch. the guarded form contains
it as a path-tagged `custom` issue (g5).

the wish demonstrates `could not hydrate ${name}: ${inner}`, which relays the symptom and stops:

```
could not hydrate Surfer: ✋ HelpfulZodValidationError: … Too small: expected string to have >=5 characters
```

`rule.require.errors-name-the-fix` sets a higher bar, and this repo already meets it elsewhere —
`getContract.ts:79` says *"declare `static schema` (zod) on X to use .contract"*, a concrete next
move. so the message must carry: which dobj failed, which nested dobj really rejected the value, and
what a caller must change. the wish's snippet demonstrates the mechanism, not the exact words.

### the timeline

```
t0  author declares the dobj                   (unchanged — schema, nested, keys)
t1  author writes the boundary schema          z.object({ surfer: Surfer.contract() })
t2  a caller sends plain json                  { surfer: { name: 'crush', spot: {…} } }
t3  the sdk parses                             → event.surfer instanceof Surfer
t4  the handler runs                           genSurfLesson(event)   // no rebuild
t5  the sdk emits the wire contract            z.toJSONSchema(schema, { io: 'input' })
t6  a downstream codegen reads x-domain-object → unchanged, still names the dobj
```

the only new step is **t1**, and it replaces work that used to live at t4.

### what an adopter must know — the `sdk-aws-lambda` case

1. ⭐ **emit with `{ io: 'input' }` — once, in the emit helper, unconditionally.** this is the whole
   of `#17`. it is service-wide rather than per-handler: `getAllLambdaContracts` walks every handler,
   so one adopted position takes down introspection for the entire service. the throw comes from
   **zod**, so its message cannot name our fix
   - ⚠️ **the OUTPUT border takes the flag too.** `#17` states it as *"`{ io: 'input' }` for the
     input schema; the output schema correctly stays `io: 'output'`"* — **wrong under this design**,
     and the likeliest way an adopter ships a half-fix. `io` names the side of the *contract*, not
     the border of the *endpoint*: the output border's in-side is *what the endpoint hands back*,
     which is the wire shape it must publish. both borders take `{ io: 'input' }`
2. ⚠️ **`#17` is written about a `.transform()`. we ship a `z.codec`.** the two throw different
   messages — *"Transforms cannot be represented"* vs *"Custom types cannot be represented"* (g25,
   g26). `{ io: 'input' }` fixes both, but `#17`'s crossed test should exercise a real
   `X.contract()` position, or it leaves the codec path in the blind spot it exists to close
3. **the migration is mechanical**: `X.contract` → `X.contract()`, `.contract.ref(by)` →
   `.contract().ref(by)`, `.ref('ref')` → `.ref()`. all three are compile-time loud
4. **if `#17` has not landed**, `{ unrepresentable: 'any' }` emits a lossy but non-throw schema
   (g26). a bridge, not a destination
5. **a dobj declaration needs no change.** no opt-in line, no new base class

⚠️ the one item this vision cannot tell them: whether their downstream codegen truly keys on
`x-domain-object` (q7) — inferred from `getContract.ts:13-19`, never checked against a live consumer.

## 4. mental model

### how an author would tell a friend

> "`.contract()` is the dobj's boundary. json goes in, the real object comes out. if you want to
> *describe* that boundary instead of cross it, ask for its input face."

### the analogies that fit

- **customs at the border.** the contract inspects the crate, unpacks it, and hands you the object.
  an emit is the published customs form — what you must supply
- **`z.coerce.string()`, one level up.** zod already ships schemas that coerce *into* a type. this is
  that idea aimed at a domain object
- **`.build` for the wire.** `X.build(props)` turns props into an instance in code. `X.contract()`
  is the schema that does it at the boundary

### terms — theirs vs ours

| they say | we say | note |
|---|---|---|
| "parse it into a Surfer" | the contract | the boundary does it; no extra word |
| "hydrate" | hydrate | already ours — for the *nested* step |
| "cast it" | ⛔ | a cast asserts and lies; a contract validates and constructs |
| "the schema" | `.schema` validates, `.contract()` crosses | two jobs, two words |

that last row is the vocabulary win: today an author who wants an instance reaches for `as`, because
no word exists for what they want. now the contract is that word.

## 5. evaluation

### against the wish's acceptance

| criterion | verdict |
|---|---|
| a position parses wire json into an `X` instance | ✅ reproduced in-repo on a real `DomainEntity` (g10) |
| `z.infer` is `X`, not `any`, and rejects a wrong shape | ✅ compiled (g22, g32), negative control consumed |
| `z.input` stays the plain wire shape | ✅ compiled (g11); see a2 for the nuance |
| the pragma survives `io: 'input'` | ✅ reproduced, incl. through an array item (g3, g16) |
| a ctor failure is a zod issue, not a throw | ✅ reproduced — the unguarded form genuinely escapes (g4/g5) |
| the dobj's own `.nested` resolves | ✅ reproduced, to depth 3 (g41a) |
| ⭐ one declaration serves both concerns | ✅ verified from a single schema object (g31) |
| ⭐ the round trip holds | ✅ identity at depth 3; superset under `.default()` (g41) |
| ⭐ `any` appears nowhere on the surface | ✅ every reachable form is typed; the untyped one is removed |
| `.contract` used bare is unchanged — additive | ❌ **NOT met — deliberately.** see below |

**the last criterion is traded away, with the wisher's authorization**, and is scored as a miss
rather than re-read. three breaks, bundled in one release:

1. the bare `X.contract` is **removed** as a schema (f10)
2. `.ref` moves onto the call, gains a real type, and `.ref('ref')` becomes `.ref()` (f8, f11)
3. the call **always coerces** (f2), so a position that parsed to a plain object now parses to an
   instance, and its emit needs `{ io: 'input' }`

the wisher's ground: *"we can break backcompat for ref here, thats fine to make it good"*, *"theres
not many consumers yet"*, *"we literally dont care about backcompat for this. we're the only
consumers."* what the trade buys: **`any` leaves the surface entirely**, and the removal **deletes
the zod-internals bet** with it.

### pros

- deletes the hand-rebuild block, the largest source of boundary boilerplate
- turns a silent `any` into a compiler-checked position — the quiet headline
- removes the `as` temptation exactly where it bites hardest
- **costs each dobj zero** — no opt-in line, no changed base class
- **one word at every boundary** — no per-position judgment about which form to reach for
- **no dependency internals** — a plain function, so no undocumented zod behavior ships

### cons

- ⚠️ **it is a break in backcompat**, and the wish asked for an additive change. mechanical and
  compile-time loud, but a consumer must still make the migration
- **`io: 'output'` emit throws**, and `'output'` is zod's default. accurate rather than a defect,
  with three caller-side escapes — but the throw comes from zod, so it cannot name our fix. **this is
  the weakest seam**
- **one extra ctor per response** at an output position (g41d). measured harmless; not free
- ⚠️ **the round trip is a superset under `.default()`** (g41b) — stable, but not an identity
- **double validation**: the contract validates, then the constructor validates the same props
  again. addressed by `{ skip: { schema: true } }` (f3, measured safe at g13)
- the callable contract is unusual enough that a reader may not expect `X.contract` to be invocable;
  discoverability rests on the docs and the type's hover text

### edge cases, and the pit of success

| edge | how the design keeps the author safe |
|---|---|
| **a key-only ref, coerced** | `.ref(by)` yields a plain key schema with **no call signature**, so `X.contract().ref('primary')()` is a **compile error** (g32b). the runtime hazard g8 proved is closed by construction, not by a doc-note |
| **`.ref` dropped by a chain** | a zod chain op returns a fresh schema without `.ref` — the extant hazard (`getContract.ts:20-23`). the doc-note moves to the call |
| **a ctor throw** | contained as a `custom` issue on the field path, so `if (!result.success)` still catches it. the naive form does not (g4) |
| **a nested dobj stricter than its parent field declares** | the **only reachable** path to a ctor throw. any test of the guard must use this shape, or it proves none of the claim |
| **`null` / optional / arrays** | chain normally; types stay `X \| null` and `X[]` (g14); the pragma rides the array item (g16) |
| **a detached `.contract`** | ⚠️ `const c = X.contract; c()` widens the captured param to `unknown`, silently (g15). doc-note: call it on the class. the impl must also fail loud at runtime when `this` lacks `.schema` |
| **a dobj with no schema, or a joi/yup schema** | the same fail-fast `ConstraintError` `.contract` already raises (`getContract.ts:79`, `:86`) |
| **repeat access** | **memoized** — the readme already promises it per class (`readme.md:574`), and a fresh instance per call would break that promise silently. one `WeakMap`, the device `getContract.ts:57` already uses. covers the call **and** each `.ref` variant |
| **an author who writes `X.contract` bare** | **fails at every use** — the position infers `unknown` (g33c), so each read is a compile error. at runtime the misuse **throws** with *"expected a Zod schema"* (g34) |
| **a full dobj supplied to a `.ref()` position** | ✅ **pruned by native zod parse** (g42). a `Surfer` **instance** with `{ uuid, name, spot }` at a `.ref()` field yields `{ uuid }` — a plain `Object`, extras and nested stripped, no error. the union tries **primary first** (`getContractRef.ts:235-244`), so a value that carries both keys reduces to the primary ref |
| ⚠️ **a `.ref()` on a dobj whose primary key is OPTIONAL** | ❌ **a live defect** — see q24. yields `{}` for a payload that carries only the unique key |
| **a new dobj** | needs **no** opt-in — reachable the moment the class exists |

### ⭐ the clamps this must ship with

per `rule.require.clamp-edge-cases`, every guarantee ships with a regression clamp. much of this
surface is invisible to an ordinary test — a type that silently widens, a removed form that must stay
removed, a pragma that rides an emit. **the clamp must bite**: every type clamp carries a negative
control that fails if the guarantee is lost.

| # | what regresses silently | the clamp | goes red when |
|---|---|---|---|
| c1 | the position erases to `any` | `IsAny<z.infer<…>['surfer']> = false` | the type widens |
| c2 | the position stops to name the class | `extends WithImmute<X> ? true : false = true` | `.clone` or the class is lost |
| c3 | the input side stops acceptance of wire json | a bare object literal typed as `z.input<…>` | the input face hardens to a class |
| c4 | `.ref` re-erases to `any` | `IsAny<z.infer<…ref('primary')>> = false` + a wrong-key `@ts-expect-error` | f8's types regress |
| c5 | `.ref()` stops to yield the union | assert both a primary-shaped and a unique-shaped value fit `.ref()`, and that neither narrow form accepts the other's key | f11 regresses |
| c6 | a ref becomes re-coercible | `@ts-expect-error` on `X.contract().ref('primary')()` | the g8 hazard reopens |
| c7 | ⭐ the bare property regains a schema face | runtime: `X.contract instanceof z.ZodType === false`, and `z.object({ x: X.contract }).parse(…)` **throws** — assert the message says *"expected a Zod schema"*, not merely that a throw occurred | the bridge creeps back |
| c8 | ⭐ the bare position stops rejection at compile | `IsAny<…> = false` at the bare position, plus a consumed `@ts-expect-error` on any **use** of the field | `any` returns, or the position becomes usable |
| c9 | a ctor throw escapes `safeParse` | the **reachable** path: a payload the parent accepts and the **nested** dobj rejects | the guard is dropped |
| c10 | the guard's message stops to name the fix | assert the message names the dobj **and** the next move | it degrades to a bare relay |
| c11 | a hydration error gets buried | assert `NestedDomainObjectHydrationError`'s own text survives | a wrapper flattens it |
| c12 | the pragma stops to ride `io: 'input'` | snapshot the emit, incl. through an **array item** | the pragma is lost |
| c13 | ⭐ one declaration stops to serve both concerns | from **one** schema object: the `{ io: 'input' }` emit is the wire shape **and** `.parse` yields an instance | the two faces diverge |
| c14 | ⭐ the round trip breaks | `z.encode(s, s.parse(wire))` equals `wire` at **depth 3**; and a `.default()` case asserts the **superset**, so the exception stays documented rather than rediscovered | encode drifts, or immute leaks |
| c15 | ⭐ decode stops to be idempotent | `decode(decode(wire))` equals `decode(wire)` | an output position starts to corrupt |

#### q24 — the three surfaces, and which one is wrong

| surface | what it says about a primary ref | |
|---|---|---|
| the **type** — `RefByPrimary.type.ts:13` | `Required<Pick<InstanceType<TDobj>, RefKeysPrimary<TDobj>[number]>>` | key **required** ✅ |
| the **runtime ctor** — `RefByPrimary.ts:51-62` | throws `BadRequestError: primary key '…' is undefined; primary keys must have defined values at reference time` | key **required** ✅ |
| the **schema** — `getContractRef.ts:123` | `schema.pick({ uuid: true })` — inherits `.optional()` from the source | key **optional** ❌ |

`pick` preserves optionality; `Required<>` does not. so the schema silently disagrees with the type
it claims to represent. **that is why this blocks f8**: f8 types `.ref('primary')` as
`ZodType<RefByPrimary<TClass>>` — literally `ZodType<{ uuid: string }>` — while the runtime accepts
`{}`. the type and the runtime would lie to each other, at the exact position this vision exists to
make honest.

**the fix** — mirror `Required<>` in the pick, inside `pickDeclaredKeys`:

```ts
return schema.pick(
  Object.fromEntries(keys.map((key): [string, true] => [key, true])),
).required();   // ← a ref must require its own key fields
```

the fallback the wisher expects then happens for free, because `buildContractRef` already pushes
primary before unique (`:235-244`):

```
{ uuid, name, spot }  →  primary ✅            →  { uuid }
{ name, spot }        →  primary ❌ → unique ✅ →  { name }    ⭐ the fallback
{ spot }              →  both ❌               →  a real zod error, not `{}`
```

⚠️ **the one open item**: this lib never imports `z` as a **value** — `getContractRef.ts:11-21`
derives every sub-schema from the author's schema instance. so research must confirm `.required()`
is on the zod object **instance** api; if it is not, the fallback is a per-field `.unwrap()` over
`schema.shape[key]`. that is a mechanical question, not a design one.

  stopped at the first wall); it claimed the plain-call form would be `any` (read off its own sketch,

  you publish it**. every claim in this document now cites a run
- ⭐ **the largest risk was cured by deletion of a feature nobody wanted.** the callable-schema bridge
  was carried for several rounds as *"the sharpest edge in the proposal"* — a bet on a zod internal.
  it existed only to keep a backcompat requirement the wisher had never been asked about. a
  constraint inherited from the wish and treated as fixed is the same failure class as the five
  above, one level up
- **the parens are a permanent residue.** `X.contract.coerce()` cannot be typed — a rule of the

- **`safeParse` throws on the removed form** rather than a return of `{ success: false }` (g36), so

- **the analogy strains at the edges.** `z.coerce.string()` never fails loudly. a contract can fail
  with a rich error. the borrowed intuition is right for intent, slightly wrong for temperament
- **the round trip is a superset under `.default()`.** honest, stable, and documented — but it means

## ⚠️ addendum — what execution measured differently (this text is preserved as approved; read this too)

### 1. the detached receiver — refused at compile, not silently widened

the edge-case table records *"⚠️ `const c = X.contract; c()` widens the captured param to `unknown`,
**silently** (g15). the impl must also **fail loud at runtime** when `this` lacks `.schema`."*

**measured, both halves come out better than feared.** the `this` parameter is bound on a real
constructor type, and a standalone call supplies `void` for `this` — which cannot satisfy that
bound. so the detach is a **compile error**, never a silent widen. and the runtime demand is
**moot**: the returned fn closes over its dobj and reads no `this` at all, so there is no state
where `this` lacks `.schema` to detect — a detached call is refused by the compiler yet would be
*correct* if it ran.

a compile refusal plus a correct runtime beats a runtime throw on both axes, so the demand is
recorded as **superseded**, not as unmet. clamped at `getContract.coerce.test.ts` with a **consumed**
`@ts-expect-error`, so a future widen fails `tsc` on the unused directive.

### 2. f9 reopened at execution

**not one line above is rewritten.** this vision is the artifact the wisher approved, so it stays as
approved. one decision in it did **not** survive contact with a fact neither party had checked, and

**f9 was approved as `z.codec`. the shipped surface is `.transform()`.** the cause is a dependency
fact, not a change of taste: zod is a **devDependency**, and every zod import in `src/` is
`import type`. `z.codec(...)` needs `z` as a **value**, so it is unreachable from this lib. the zod
schema **instance** api was enumerated to be sure (g43a, 55 methods): `transform` / `pipe` /
`overwrite` / `required` are present, **`codec` is not**.

**the choice is deliberate and reversible.** `.transform()` keeps this lib free of a runtime schema
dependency, and both shipped concerns are complete without an encode. the reworks are **asymmetric**:
transform → codec later is clean and purely additive (it would only ADD `z.encode`), while codec →
transform later cannot un-ship a runtime dependency. that asymmetry is why the dependency-free form
shipped first — and why f9 rides to the wisher's end-of-road council rather than halts the drive.
