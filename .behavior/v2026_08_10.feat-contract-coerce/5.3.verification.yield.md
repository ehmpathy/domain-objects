### v2 — the q24 vacuous-ref fallback had no acceptance-grain proof → **fixed**

the feature's single historical **blocker**-severity defect (i005/i010 → i011): with an optional
primary key, the primary arm succeeded *vacuously* and a real reference came back as `{}`. covered
exhaustively at unit grain (matrix tables A/B), absent from the journey suite — and the readme

**fixed**: `when('a caller supplies only the UNIQUE key (the q24 fallback)')` — the fallback, the

### ⭐ v3 — a FAILHIDE of my own authorship, caught mid-dogfood → **fixed, and the class audited**

the v2 clamp's first draft used `expect(getError(() => …)).toBeDefined()`. the dogfood run came back
**2 passed, 2 failed** — two of four clamps stayed green under the reverted defect. rather than
accept the split, i probed it:

```
GETERROR returned: "Error: NoErrorThrownError: no error was thrown"
GETERROR isDefined: true
GETERROR isError:   true
```

⛔ **`getError` returns a `NoErrorThrownError` when the subject does NOT throw — and that IS an
`Error` instance.** so `expect(error).toBeDefined()` and `expect(error).toBeInstanceOf(Error)` pass
in **both** directions. a clamp built on either is a `rule.forbid.failhide` violation: it reads as
coverage and guards no behavior.

it also confirmed the fact beneath it: with `.required()` reverted, `.ref('primary')` on a
unique-only payload returns **`success: true, data: {}`** — it never throws, so the throw channel
was the wrong channel to assert on in the first place.

**fixed**: both clamps rewritten onto `safeParse().success`, which cannot be satisfied by a
non-throw. **re-dogfooded: 0 passed, 4 failed** — all four now bite.

**and the class was audited, not just the instance** — grep across `src/` for
`expect(error).toBeDefined()` / `.toBeInstanceOf(Error)` / `.toBeTruthy()` returns **only the two i
had just written**. every other `getError` clamp in the repo asserts the error's **class**
(`toBeInstanceOf(ConstraintError)`) or its **message** (`toContain(...)`), neither of which a
`NoErrorThrownError` satisfies. the class was closed at the moment of introduction.

⭐ the rule this yields, recorded in the test file itself: **a `getError` clamp must assert the
error's CLASS or MESSAGE — or sidestep the throw channel entirely.** a bare presence check is a
failhide.

### ⭐ v5 — `.optional()` had no PARSE clamp, while its twin `.nullable()` did → **fixed**

found in the `has-behavior-coverage` self-review by a walk of the chain ops the vision's edge table
names, with one question asked of each: *is it clamped at BOTH concerns?*

> *"a chain op returns a fresh schema, so 'the coerce rides through `.nullable()`' is a claim that

⭐ **that argument is about chain ops in general, and it was applied to one op and not its twin.**

absent-key clamp stayed green and is **labelled in the file as a positive control**, since a no-op
