## ⚠️ the one open fulcrum — f9 reopened by a fact neither party had checked

**`z.codec(...)` is unreachable from this lib.** zod / joi / yup are **devDependencies only**, there
is no `peerDependencies` block, and every non-test `src/` import of zod is `import type`
(`package.json:64-108`). measured (g43a): a `z.object` instance exposes 55 methods —
`transform` / `pipe` / `overwrite` / `required` yes, **`codec` no**. so a bidirectional constructor
is out of reach without a value import.

| | `.transform()` | `z.codec()` |
|---|---|---|
| reachable from the instance | ✅ | ❌ needs a value import |
| dependency cost | **none** | ⛔ zod becomes a runtime dep (or an optional peer + lazy import) |
| instantiation + introspection | ✅ both | ✅ both |
| `z.encode` → wire props | ❌ throws `$ZodEncodeError` (g43d) | ✅ |

**best guess: `.transform()`**, on three grounds — the dependency contract outweighs an operation no
caller makes (an sdk parses at both borders; g29/g39/g41d proved the wire bytes match and the decode
is idempotent); both usecases ship complete; and the reworks are **asymmetric** — transform → codec
later is clean and additive, while codec → transform later cannot un-ship a runtime dependency
without a break.

**awaits the wisher's call.** the impl below is written so the swap is a one-site change:
`buildContract` in `getContract.ts`, the single `.transform(...)` line.

**shipped on the best guess, and measured green** (g44): `.parse(wire)` yields a live instance with
`.clone`; `{ io: 'input' }` emits the wire shape + pragma; a nested `.contract()` hydrates inside a
parent `z.object`; a ctor throw is contained as a path-tagged `custom` issue. the one visible cost is
the fulcrum's known one — `z.toJSONSchema` with the DEFAULT `io` now **throws**
`Transforms cannot be represented in JSON Schema`, so **every** emit must pass `{ io: 'input' }`
(which the briefs already state is unconditional at both borders).

## 🟡 the second open question — `.ref('ref')` still succeeds at runtime

surfaced by `review.self/has-pruned-backcompat`. f11 replaced `.ref('ref')` with `.ref()`, and the
TS overloads refuse the argument (a **compile error**, clamped in table E). but the runtime is
`(by) => getContractRef(dobj, by ?? 'ref')`, so a **js** caller who passes `'ref'` still gets the
union rather than a throw. nobody asked for that, so it is reported rather than quietly kept.

**best guess: keep it.** `'ref'` is not the old *form*, it is the *grain name* — f11 removed the
argument requirement, never the grain, and `by: 'ref'` is still the value stamped onto the wire
(g37). a throw would put the argument the api refuses at odds with the value the api publishes, so a
reader who echoed the pragma back would fail. the value is also the memo key and the recursion
parameter, and the `:238` guard still **throws** on any *unrecognized* `by` — so the permissiveness
is bounded to the one legitimate grain.

**clean rework if the wisher disagrees**: one `if` in `getContract.ts`'s `.ref` value, plus one
clamp. no ripple. **revisit trigger**: if the pragma value ever stops to be `'ref'`, the argument
must stop to be accepted in the same change.
